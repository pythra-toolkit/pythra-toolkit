perf: Cythonize Key map lookups to strict C-level string hashes

Architectural Changes:
- Previously, `reconciler.py` and `reconciler_cython.pyx` were performing dictionary lookups (`previous_map[key]`) and set differences (`old_keys_set - new_keys_set`) using raw `Key` Python objects. 
- Python objects require invoking rich equality (`__eq__`) and generic object hashing rules on every single dictionary operation. In large `VirtualList` arrays, this memory thrashing scales poorly.
- We have completely eliminated Python object dictionary map lookups inside `cython_diff_node_recursive` and `cython_diff_children_recursive`.
- Keys (like `Key("my_button")` or `Key(123)`) are now mathematically resolved down to their strict underlying string representations (`"my_button"`, `"123"`) via `str(key.value)` immediately at the start of hot loops and cached.
- `reconciler.py` now populates the `new_rendered_map` using these strict `str` primitives as dictionary keys instead of the Python wrappers themselves.

How to comply with this architectural change:
1. Reconciler Internal state: Inside `reconciler.py`, maps like `self.context_maps` must now always be addressed using strings, not raw `Key()` objects. If you call `previous_map.get()`, you must pass `str(key.value)` to ensure proper lookup.
2. Dictionary construction: The `Key` class itself is structurally intact to satisfy component APIs outwards (`Widget(key=Key('val'))`), but developers contributing to backend compiler cycles should be aware that the Reconciler sheds the wrapper object entirely internally.
